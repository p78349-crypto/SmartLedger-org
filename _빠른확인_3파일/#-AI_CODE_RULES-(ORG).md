# AI_CODE_RULES (ORG)

1) 80줄 이하 작성
• 모든 코드 파일(`.ps1`, `.py`, `.sh`)은 한 줄 길이 80자 이하를 원칙으로 한다.

• 함수 길이는 80줄 이하를 권장하며, 초과 시 분리를 우선 검토한다.

• 80줄 초과가 예상되면 기능을 즉시 헬퍼 모듈로 분리한다.

• 검증: `.\tools\check-line-limits.ps1` 실행.

2) 작업 단위 300라인 제한
• 단일 작업 사이클에서의 변경 사항(신규+수정)은 300라인 내외로 제한하여 품질과 안정성을 우선한다.

• 대규모 변경은 3개 이상의 작업 단위로 분할하여 단계적으로 진행한다.

3) 작업 3개 완료 + 상세작업기록
• 매 사이클마다 최소 3개 작업을 완료하고 `WORK_LOG_DETAIL.md`에 기록한다.

• 필수 기록 항목: 작업명, 변경 파일, 검증 결과(에러 0), 운영 영향 및 복구 포인트.

4) 로컬 백업 자동화
• 규칙 및 운영 문서 변경 시 `backups` 폴더에 즉시 백업한다.

• 파일명 규칙: `파일명-YYYYMMDD-HHMMSS.ext`

• 필수 백업 대상: `#-AI_CODE_RULES-(ORG).md`, `WORK_LOG_DETAIL.md`.

작업 시작전 원본 파일 별도 폴더만들고 복사후 수정작업 진행한다.

5) 기능 모듈화 및 시작 시점 관리
• 5.1 시작 시점 모듈화: 구현 전에 엔트리 파일과 헬퍼 파일의 경계를 먼저 결정한다(사후 분해 금지).

• 5.2 재작업 방지 게이트: 작업 시작 전 `모듈화 계획: PASS`를 반드시 확인한다.

• 5.3 테스트 모듈화: 테스트 스크립트 역시 80줄 제한을 준수하며 모듈 구조로 작성한다.

6) 고위험 작업 안전수칙
• 복잡도가 높거나 대규모 리팩터링 시 원본을 별도 폴더에 보관 후 단계적으로 진행한다.

• 모든 변경은 파일 에러 0 상태를 유지해야 한다.

7) 저작권 준수
• 저작권 위반 소지가 있는 코드는 사용하지 않는다.

8) 코드 보안 점검 및 AI 모델 정책 (데이터 유출 방지 필수)
• 하드코딩된 비밀번호, API 키, 개인정보 노출 여부를 작업 완료 후 반드시 체크한다.

• 보안 원칙: 외부 유출 시 피해가 낮은 정보/동작만 허용한다.

• AI 모델 보안: 자료 유출 사고 방지를 위해 Qwen 등 중국계 AI 모델 및 서비스 사용을 엄격히 금지한다.

• 검증된 서구권 오픈소스 모델(예: Moondream2, Llama-3.2-Vision, Gemma 등)만 로컬 환경에서 구동하여 데이터의 외부 전송을 원천 차단한다.

9) 대규모 리팩터링 및 원본 보존
• 원본 격리: 300줄 초과 리팩터링 시, 신규 폴더를 생성하고 원본을 복사하여 작업한다.

• 원본 유지: 원본 폴더는 수정 없이 초기 상태를 유지하며, 에러 발생 시 복구 참조용으로만 사용한다.

• 모듈화 확보: 코드 분리 시 기능 단위로 모듈화하여 코드 품질과 유지보수성을 극대화한다.

10) 환경 의존성 및 에러 처리 표준
환경 명시: 외부 라이브러리나 특정 OS 의존성이 발생하는 경우, 스크립트 상단 주석 또는 REQUIREMENTS.md 파일에 해당 내용을 반드시 명시한다.

예외 처리: 모든 엔트리 포인트 스크립트에는 Try-Catch 구문을 포함하여 예외 처리를 수행하며, 에러 발생 시 사용자에게 **복구 방법(예: 9번 규칙에서 생성한 원본 파일 위치 등)**을 명확히 안내한다.

11) 작업 요약 및 컨텍스트 전달 (Hand-over)

작업 요약: 매 사이클 종료 시, 수행한 작업의 핵심 변경 사항을 3줄 이내로 요약하여 AI에게 전달한다.

연속성 확보: 다음 작업자가(혹은 다음 세션의 AI가) 이전 상태를 즉시 파악할 수 있도록 WORK_LOG_DETAIL.md의 최상단에 '현재 시스템 상태 요약' 섹션을 유지한다.

3. `WORK_LOG_DETAIL.md`에 3개 작업 완료 기록 확인

4. `backups` 폴더에 로컬 백업 생성 확인

5. 시작 시 `tools/start-task-guard.ps1`가 있으면 실행하고,
   없으면 작업 로그 상단에 `모듈화 계획: PASS`를 수동 기록
