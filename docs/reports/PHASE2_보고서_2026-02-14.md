## 2️⃣ 새로운 기능 상세 설명

### A. 미국 상품 임포트 시스템 (`UsProductImporter`)

**📊 데이터 소스**
- 파일: `FoodData_Central_branded_food_json_2025-12-18.json`
- 크기: 3.3GB (매우 큼)
- 상품 수: 70,000개 이상의 미국 브랜드 식품
- 바코드: UPC-A (미국/캐나다 표준)

**🔧 기술 특징**
- **스트리밍 JSON 파서**: 3GB 파일을 메모리에 로드하지 않고 처리
  - 메모리 오버플로우 방지
  - 라인 단위로 처리 (매우 효율적)
  
- **영양 정보 추출**: 4가지 주요 영양소
  - 에너지 (칼로리) - USDA ID: 1008
  - 단백질 - USDA ID: 1003
  - 지방 - USDA ID: 1004
  - 탄수화물 - USDA ID: 1005
  
- **자동 카테고리 분류**
  - 음료 (Beverages)
  - 육류 제품 (Meat Products)
  - 유제품 (Dairy)
  - 스낵 (Snacks)
  - 등등...
  
- **기본 수량**: 1개 (미국 표준)

**📈 임포트 성능**
- 배치 크기: 1,000개씩 처리
- 진행률 실시간 업데이트
- 오류 발생 시 자동 로깅 및 계속 진행

---

### B. 일본 상품 임포트 시스템 (`JapanProductImporter`)

**📊 데이터 소스**
- 파일: `20201225-mxt_kagsei-mext_*.xlsx` (여러 파일)
- 직접 형식: MEXT 가세이 데이터
- 상품 수: 10,000개 이상의 일본 식품
- 바코드: JAN (일본 표준, 13자리)

**🔧 기술 특징**
- **CSV 파서** (사전에 Excel → CSV 변환 필요)
  - 간단하고 안정적
  - 큰 용량 파일도 빠르게 처리
  
- **JAN 바코드 검증**
  - 13자리 숫자 확인
  - 유효하지 않은 바코드 자동 스킵
  
- **일본어 카테고리 번역**
  - 飲 → 음료 (Beverages)
  - 肉 → 육류 (Meat)
  - 乳 → 유제품 (Dairy)
  - 野 → 채소 (Vegetables)
  - 등등...
  
- **기본 수량**: 2개 (일본 표준 - 편의점 패킹 기준)

**📈 임포트 성능**
- 배치 크기: 1,000개씩 처리
- 진행률 실시간 업데이트
- 카테고리 자동 매핑

---

### C. 글로벌 API 서비스 (`OpenFoodFactsService`)

**📊 데이터 소스**
- API: https://world.openfoodfacts.org/api/v0/products/{바코드}
- 데이터 범위: 전 세계 100만 개 이상의 상품
- 비용: 무료 (제한 없음)
- 언어: 다국어 지원

**🔧 기술 특징**
- **빠른 응답**: 100~500ms (캐시 사용 시 <1ms)
- **응답 캐싱**: 500개 항목 LRU 캐시
  - 반복 검색 시 즉시 응답
  - 메모리 효율적
  
- **바코드 접두사 자동 인식**
  - 60-64, 70-74: 영국 🇬🇧
  - 30-37: 프랑스 🇫🇷
  - 40-43: 독일 🇩🇪
  - 45, 49: 일본 🇯🇵
  - 50: 영국 🇬🇧
  - 55: 브라질 🇧🇷
  - 88: 한국 🇰🇷
  - 90-91, 3: 미국 🇺🇸
  
- **다국어 상품명 지원**
  - 한글 (product_name_ko)
  - 영문 (product_name_en)
  - 일본어 (product_name_ja)
  
- **우아한 실패 처리**
  - 상품을 찾지 못해도 오류 없음
  - null 반환 (다른 메서드로 대체)

## 3️⃣ PDA 화면 바코드 스캔 3단계 처리 흐름

### 사용자가 바코드를 스캔할 때:

```
┌─────────────────────────────────┐
│  바코드 스캔 (예: 8801040234515) │
└────────────┬────────────────────┘
             │
       ▼─────▼─────────────────────────┐
       ① 로컬 데이터베이스 검색 (1~100ms)
       │  
       ├─ ✅ 찾음 → 자동 입력 (초록색 ✓)
       │  └─ 수량 자동 입력: 한국=2개
       │
       └─ ❌ 못 찾음 (로컬에 없음)
             │
             ▼─────────────────────────┐
             ② OpenFoodFacts API 검색 (100~500ms)
             │
             ├─ ✅ 찾음 → 자동 입력 (주황색 !)
             │  └─ 수량 자동 입력: 국가 기준
             │
             └─ ❌ 못 찾음 (API도 없음, 매우 드문 경우)
                   │
                   ▼─────────────────────────┐
                   ③ 로컬 인벤토리 검색
                   │
                   ├─ ✅ 찾음 → 수량=1
                   └─ ❌ 못 찾음 → 수동 입력 필요
```

### 3단계 처리의 장점
- ✅ 빠른 응답: 로컬 DB가 최우선 (1ms)
- ✅ 광범위한 커버리지: 100만 개 상품 (API)
- ✅ 사용자 경험: 스캔 후 자동 수량 입력
- ✅ 신뢰성: 세 가지 폴백 메커니즘

```

   → 로컬 DB에서 즉시 발견 (1ms)
   → 수량: 2개 자동 입력
   → 상태: ✓ 초록색 (완료)

2️⃣ 미국 콜라 바코드 스캔
   → 로컬 DB에서 발견 (임포트 후)

   → 상태: ✓ 초록색 (완료)

3️⃣ 일본 라면 바코드 스캔
   → 로컬 DB에서 발견 (임포트 후)
   → 수량: 2개 자동 입력
   → 상태: ✓ 초록색 (완료)

4️⃣ 모르는 바코드 스캔
   → 로컬 DB 검색 실패
   → OpenFoodFacts API 검색 (100~500ms)
   → 발견 시: 상태: ! 주황색 (API 조회)
   → 미발견: 수동 입력 필요
```

- 📊 동시 검색: 100개 이상 동시 가능

## 🔟 주요 기술 특징

### 1. 메모리 효율성
- **스트리밍 JSON 파서**: 3.3GB 파일도 메모리 오버플로우 없음
- **LRU 캐시**: 500개 항목만 메모리에 유지
- **배치 처리**: 1,000개씩 DB에 저장

### 2. 응답 속도
- **L1 (메모리):** <1ms
- **L3 (DB):** <100ms
- **API:** 100~500ms (캐시 시 <1ms)

### 3. 신뢰성
- **다단계 폴백**: 로컬 → API → 수동입력
- **오류 처리**: 문제 발생 시 계속 진행
- **진행률 표시**: 사용자가 상태 확인 가능

### 4. 확장성
- **국가 추가 용이**: 같은 스키마 사용
- **API 주기적 동기화**: 추후 기능 가능
- **다국어 지원**: 한글/영문/일본어 포함

## 1️⃣3️⃣ 문제 해결 가이드

### Q: 3GB JSON 파일이 너무 크면?
**A:** 스트리밍 파서 사용 → 라인 단위 처리 → 메모리 안전

### Q: Excel 파일은 어떻게?
**A:** CSV로 먼저 변환 → 간단한 CSV 파서로 처리

### Q: 바코드를 못 찾으면?
**A:** 3단계 폴백 → 마지막에 API 조회 → 그래도 없으면 수동 입력

### Q: API가 느리면?
**A:** LRU 캐시 (500개) → 반복 검색은 <1ms

### Q: 어느 나라 상품을 모르면?
**A:** 바코드 접두사로 자동 인식 → 국가 코드 자동 설정
